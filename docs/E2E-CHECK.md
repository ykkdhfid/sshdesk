# 前后端联调检查

一句话结论：**接口 20 项、浏览器流程 26 项全部通过**；过程中发现并修掉 3 个真实问题，其中一个
会让用户照着提示操作却永远连不上服务器。

## 怎么复现

```bash
# 1) 服务端（演示用令牌）
SSHDESK_HOME=/tmp/sshdesk-web python3 -m sshdesk web --port 18081 --token demo-token-abc

# 2) 靶机（演示用 127.0.0.1:2222，密码 test123）
python3 tools/mock_sshd.py

# 3) 先确认一次主机指纹，否则所有连接都会被 TOFU 拦下
SSHDESK_HOME=/tmp/sshdesk-web python3 -m sshdesk test 本地靶机 --login --trust-host
```

## 接口契约

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/` | 无 | 单页入口 |
| GET | `/api/health` | 无 | 存活探测，返回服务器台数 |
| POST | `/api/login` | 无 | 校验令牌，下发 `httponly` cookie；同 IP 60 秒内失败 5 次即限流 |
| POST | `/api/logout` | 无 | 清 cookie |
| GET | `/api/servers` | cookie | 服务器列表 |
| GET | `/api/monitor/{id}` | cookie | 一次 SSH 采集 CPU/内存/磁盘；失败返回 **502**（不是 500） |
| WS | `/ws/term/{id}` | cookie 或 `?token=` | 终端通道 |

WebSocket 的两条约定值得单独记下：

- **先 `accept()` 再校验**。ASGI 规范下 accept 之前 close 会被降级成 HTTP 403，浏览器就读不到
  自定义关闭码了。
- **终端输出走二进制帧**（`send_bytes`），只有 `ready` / `error` / `closed` 这类控制消息才是 JSON 文本。
  前端 `ws.binaryType = "arraybuffer"` 后直接喂给 xterm。

关闭码语义：

| 码 | 含义 | 前端行为 |
|---|---|---|
| 4401 | 未登录 / 令牌失效 | 跳回登录页 |
| 4404 | 服务器 id 不存在 | 提示后回列表 |
| 4502 | SSH 连接或认证失败 | 停在终端页，显示错误与建议 |
| 1000 | 正常结束（用户退出或远端断开） | 显示「已断开」并提供重连 |

## 接口层（20 项，全通过）

覆盖：静态资源 200/404、未登录 401、错令牌 401 且不下发 cookie、正确登录下发 cookie、
列表字段完整性、health、监控采集（CPU 0%、内存 17.1%）、不存在的 id 404、退出后回到 401、
WS 4401 / 4404 / ready、命令往返回显。

其中「命令往返」这条一开始是误判：测试脚本按 JSON 解析所有消息，但终端输出是二进制帧，
改了接收方式才通过——**这恰好证明协议约定写进文档是对的**。

## 前端流程（26 项，390 与 1440 各跑一遍，全通过）

登录页渲染 → 错误令牌有可见提示且停在原页 → 正确令牌进列表 → 渲染两台且计数「2 台」→
点进终端、出现提示符、状态显示「已连接」→ `echo` 回显 → **中文输入不乱码** →
状态浮层有 CPU/内存/磁盘/负载 → 关闭浮层 → 返回列表 → 退出回登录页。

全程监听 `pageerror` 与 console：没有未捕获异常。

## 修掉的三个问题

### 1）提示文案让用户永远连不上（最严重）

Web 端连不上时给的建议是：

```
python -m sshdesk test 机器名 --trust-host
```

但 `test` 子命令**只有加 `--login` 才会真的握手**，否则只做端口/banner 诊断，
不会写 `known_hosts`。用户照着敲一百遍也信任不了指纹。

改成 `test 机器名 --login --trust-host`，并在注释里写明为什么这个参数不能省。

### 2）`SSHDESK_PASSWORD` 只有一条路径认

`_resolve_password()` 只读 `password_ref` 对应的加密存储。CLI 的 `_connect()` 自己另读环境变量，
所以 `test --login` 能连、`exec` 和 **Web 端**却拿不到密码。

而拿不到密码时报的是「无法连接到服务器」——用户会去查安全组、查 sshd，实际上是缺凭据。

修了两处：

- `_resolve_password()` 增加环境变量兜底（存储值优先）。CLI / Web / 批量执行从此共用同一条取密码路径。
- 密码为空时**在连接前就拦下**，报「没有可用的登录密码」并给出三种解法，而不是等 SSH 握手失败。

### 3）缺 favicon 造成一次 404

浏览器默认请求 `/favicon.ico`。补了一个内联 SVG（`>` 提示符 + 深空底），既消掉 404，也不必多一个文件。

## 留在控制台里的一条 401

首屏 `/api/servers` 会先请求一次以探测登录态，没 cookie 时必然 401。这是**预期行为**
（前端已静默 catch），只会在浏览器开发者工具里留一行红字，普通用户看不到。没有为它改接口。

## 没覆盖到的

- **真机 47.108.222.188**：本容器到公网 22 口的连通性与 banner 已由 `sshdesk test` 单独验证过，
  但端到端流程跑在本地靶机上（避免把凭据写进演示环境）。
- **SFTP**：Web 端没有 SFTP 界面，只在桌面版里，本轮未测。
- **限流**：只在代码层确认（60 秒 5 次失败），没有专门压测。
