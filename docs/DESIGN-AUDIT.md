# 前端设计自查：23 条规范

这份文档记录 Web 界面这次改版的依据、改了什么、以及逐条自查结果。
不是"我觉得好看"，而是每条都能在代码或实测数据里对上。

---

## 为什么要改

上一版界面是一套典型的"AI 生成感"样式：紫色渐变主按钮 + 紫色投影光晕 + 同款圆角卡片堆叠。
这类样式的问题不在丑，而在**没有做决定**——它把几个默认选项拼在一起，所以一眼能看出是模板。

这次按两个前端设计 Skill 的规范重做：

| Skill | 用途 | 拿它做了什么 |
|---|---|---|
| **taste-skill**（tasteskill 2.5） | 反"AI 味"的界面判断标准 | 拒绝通用模板；地址脱敏；悬停只做微动效；一屏一个主任务 |
| **impeccable**（v4.8.0） | 设计总监级打磨流程 | 判定本界面属于 **Operate 模式**（用户在完成任务，不是在看营销页）；按 `craft-floor` 的禁令逐条清理；补齐组件状态 |

Impeccable 的 Operate 模式有一条关键的判断：

> 产品界面的失败模式不是"太平淡"，而是"没必要的奇怪"。
> 标准是**有依据的熟悉感**——工具应该消失到任务里去。

这句话决定了整个方向：这不是一个可以随便玩花活的地方。登录、选服务器、敲命令，每一步都要求用户零学习成本。
所以"设计感"只能藏在细节里——间距、对比度、状态反馈、原生表面，而不是靠视觉特效。

## 星空的严肃性，和 Linux 的严肃性

用户最后给的定调只有一句：**「要把星空的严肃深邃和 Linux 作为纯文本系统的严肃结合在一起」**。
这句话排除了一整类做法——星空不是浪漫的、不是撒糖的、不是深紫配光晕的那种"宇宙感海报"。
它要的是两样东西叠在一起：**背景的深度**，和**前景的秩序**。

由此定了四条，每条都能在代码里找到落点：

**1）深空底色，不是纯黑。** `#070a12`（终端区 `#04060d`）。
纯黑让文字边缘发硬、久看发累；带一点蓝相才像夜空。但它必须暗到"几乎不反射"，否则星星就浮在灰面上。

**2）星点是 1px 硬点，像设备指示灯，不做柔光。**
没有 blur、没有 glow。亮度按星等分层（`.32` 到 `.80`）。

星点**不是写死在背景图里**，而是 `app.js` 里逐颗生成的独立元素，三个理由：

- **要闪**：每颗自己一个 `--dur`（3.4–7.6s）和 `--delay`（0–8s），相位不同，
  所以是一颗接一颗地闪，不是整片一起呼吸。线性呼吸会变成呼吸灯——那是设备状态，不是星。
  keyframes 也是"长暗短亮"：`0%` 和 `100%` 压到 `--o * .18`，只在 `38%–52%` 亮到全值。
- **要随机出现**：约五分之一是 `.rare`，用 `blink` 关键帧，18–24 秒里只存在大约 2 秒，
  其余时间透明度为 0。所以盯久了会发现星星在换位置——这比一张固定星图更像夜空。
- **要躲开输入栏**：生成落点时先取页面里 `input, textarea, button, .login-box, .server-card, .term-head, .tools`
  的包围盒，外扩 26px，落在里面就重抽（最多试 40 次）。
  1px 的点压在 token 输入框上，人会以为屏幕有坏点；压在按钮上会像渲染错误。
  窗口 resize 后 300ms 重算一次——百分比坐标不重新生成的话，原来的星会随着布局漂到输入框上。

仍保留一条约束：星点坐标在三端共用同一张百分比表（Web / tkinter Canvas / CLI 演示图），
所以三个界面里的星空是同一片星空。

**2.5）星云：三团蓝青色的雾，负责"深邃"，不负责"好看"。**
`radial-gradient` 三团（`.085` / `.062` / `.055`），位置压在左上、右上、底部，
比例在 44%–68% 之间——边缘要溢出视口，云才没有边界；一旦收在视口内，就成了三块圆斑。
色相是灰蓝 `rgb(78,104,168)`，不是紫：紫色一上来就滑向"宇宙海报"，
和"Linux 那种严肃"直接冲突。

**3）背景铺一张几乎看不见的字符网格：40px 见方，`rgba(120,145,190,.028)`。**
这是整套设计里唯一带"隐喻"的地方，也是最能回答用户那句话的地方：
终端本来就是按行列对齐的纯文本系统，光标、缩进、表格全靠列对齐。
那么它的背景理应是**那张坐标纸**，而不是一张装饰图。
透明度压到 `.028`：看得见格子，但说不清是格子——一旦压不住，就变成 Excel 底纹（第一版 `.05` / 32px 就是这个下场，被自己否掉了）。

**4）方角，等宽字。** `--radius: 2px`（原来是 6px）。
圆角会把硬边系统拉回"移动端 App 模板"，而终端里没有一个圆角。
产品名 `SSHDesk` 用等宽字排——界面上的第一句话就该说明：这是一套文本系统。

| | 之前（AI 烂大街版） | 现在 |
|---|---|---|
| 星点 | 12px 模糊光斑，随机撒 | 1px 硬点，逐颗生成，各自闪烁、随机出现 |
| 背景 | 纯渐变 | 深空 + 40px 字符网格 |
| 圆角 | 6px，卡片套卡片 | 2px，行式列表不套卡片 |
| 产品名 | 无衬线粗体 | 等宽字 |
| 强调 | 紫色渐变 + 光晕 | 单色 `#7b9df0`，无光晕 |

## 被删掉的东西（具体清单）

这些是"AI 烂大街"的具体载体，全部移除，不留兼容：

| 删掉的 | 原来的写法 | 现在 |
|---|---|---|
| 紫色渐变主按钮 | `background: linear-gradient(135deg,#8b7cf6,#5aa2ff)` | 纯色 `#7b9df0`，靠色块本身说话 |
| 紫色投影光晕 | `box-shadow: 0 4px 16px rgba(139,124,246,.28)` | 无阴影（阴影只用于需要脱离层的浮层，且带偏移+柔化） |
| 渐变文字 | 标题用渐变色填充 | 不用；强调靠字重和字号 |
| 同款圆角卡片堆叠 | 每台服务器一张带边框圆角卡片 | 改**行式列表**：分隔线 + 留白分组，行高 64px |
| 卡片上的彩色左边条 | 分组色条 `border-left: 3px` | 一个 6px 的菱形小点表示状态 |
| `--grad` 变量 | 全局渐变 token | 已删除，避免以后又被复用 |

"卡片当容器"这条是 Impeccable 明确点名的懒惰做法：

> 同尺寸的「图标 + 标题 + 文字」卡片当成页面结构；卡片是懒惰的容器，嵌套卡片永远是错的。

服务器列表的信息密度本来就低，用卡片等于给每行加了一圈没有信息量的边框。改成行式列表后，
一屏能多看几台，扫读更快。

## 23 条逐项自查

分五组。结论只有两种：**合规**（代码里能对上）和 **已改**（这次动过手）。

## 尺寸实测

同一套样式在三个真实视口跑过，截图见 `docs/`：

| 视口 | 页面 | 结果 |
|---|---|---|
| 390×780（手机，DPR 2） | 登录 / 列表 / 终端 / 状态 | 单列、留白均衡、终端可读 |
| 1024×768（平板） | 列表 | 已进入限宽，行宽不超过 760 |
| 1440×900（PC） | 登录 / 列表 / 终端 | 列表居中不拉伸；终端铺满，字号 16 |

终端在 1440 宽下如果沿用 14px，字符会细到看不清；16px 是这块屏幕上的上限——
再大，一行就装不下 `df -h` 那种 100+ 字符的输出。

## 已知取舍

- **星点数量按屏宽分两档**：窄屏 18 颗、宽屏 26 颗，不追求"满天星"。再密就会干扰阅读，这是刻意的。
- **演示 GIF 体积**：登录页有星云渐变，量化时关掉 dither 才能压到 1.5MB 以内；开抖动会翻五倍。
- **列表页留白很大**：只有两台服务器时，下半屏是空的。没有做"填充内容"的假区块，空着就是空着。
- **不用玻璃拟态做浮层**：状态面板是实色 + 边框 + 柔和阴影，因为毛玻璃在半透明背景下会糊掉一屏终端内容。
- **终端字号不做流体缩放**：`clamp()` 会让不同窗口宽度下的列数不可预测，SSH 终端需要确定的字符网格。
