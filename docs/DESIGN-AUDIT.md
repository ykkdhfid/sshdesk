# 前端设计自查：23 条规范

这份文档记录 Web 界面这次改版的依据、改了什么、以及逐条自查结果。
不是"我觉得好看"，而是每条都能在代码或实测数据里对上。

---

## 为什么要改

上一版界面是一套典型的"AI 生成感"样式：紫色渐变主按钮 + 紫色投影光晕 + 同款圆角卡片堆叠。
这类样式的问题不在丑，而在**没有做决定**——它把几个默认选项拼在一起，所以一眼能看出是模板。

这次按两个前端设计 Skill 的规范重做：

| Skill | 用途 | 拿它做了什么 |
|---|---|---|
| **taste-skill**（tasteskill 2.5） | 反"AI 味"的界面判断标准 | 拒绝通用模板；地址脱敏；悬停只做微动效；一屏一个主任务 |
| **impeccable**（v4.8.0） | 设计总监级打磨流程 | 判定本界面属于 **Operate 模式**（用户在完成任务，不是在看营销页）；按 `craft-floor` 的禁令逐条清理；补齐组件状态 |

Impeccable 的 Operate 模式有一条关键的判断：

> 产品界面的失败模式不是"太平淡"，而是"没必要的奇怪"。
> 标准是**有依据的熟悉感**——工具应该消失到任务里去。

这句话决定了整个方向：这不是一个可以随便玩花活的地方。登录、选服务器、敲命令，每一步都要求用户零学习成本。
所以"设计感"只能藏在细节里——间距、对比度、状态反馈、原生表面，而不是靠视觉特效。

## 星空这套配色是怎么定的

用户给的定调是「深色 + 星空点缀」，并明确要避开渐变紫、毛玻璃、同质化卡片。

落地时做了三个决定：

1. **底色不是纯黑，是带蓝相的深空**：`#070a12`（终端区更暗 `#04060d`）。
   纯黑会让文字边缘发硬，久了眼睛累；带一点蓝相更接近夜空的实际观感。
2. **星点是"星等分层"，不是随机撒点**：10 颗点里，少数稍亮（`.40`），多数是几乎看不见的微光（`.13`）。
   真实星空不是均匀的，全部一个亮度看起来就像屏幕坏点。
3. **星点只出现在没有内容的空场**：登录页、列表页的背景。
   终端区一点星都不放——那是要读字符的地方，背景必须绝对干净。

还有一个技术细节：星点用 `radial-gradient`，半径在移动端写 `0.5px`、宽屏写 `1px`。
因为手机上 DPR 通常是 2~3，`1px` 会被渲染成一个 2~3 物理像素的硬边方块，看着像脏点；
`0.5px` 才落成 1 个物理像素的柔光。而 PC 的 DPR=1，`0.5px` 会被抗锯齿抹成灰雾，所以宽屏必须换回 `1px`。
同一个设计在两种屏幕上要写两套参数，这是屏幕密度差异，不是响应式偷懒。

## 被删掉的东西（具体清单）

这些是"AI 烂大街"的具体载体，全部移除，不留兼容：

| 删掉的 | 原来的写法 | 现在 |
|---|---|---|
| 紫色渐变主按钮 | `background: linear-gradient(135deg,#8b7cf6,#5aa2ff)` | 纯色 `#7b9df0`，靠色块本身说话 |
| 紫色投影光晕 | `box-shadow: 0 4px 16px rgba(139,124,246,.28)` | 无阴影（阴影只用于需要脱离层的浮层，且带偏移+柔化） |
| 渐变文字 | 标题用渐变色填充 | 不用；强调靠字重和字号 |
| 同款圆角卡片堆叠 | 每台服务器一张带边框圆角卡片 | 改**行式列表**：分隔线 + 留白分组，行高 64px |
| 卡片上的彩色左边条 | 分组色条 `border-left: 3px` | 一个 6px 的菱形小点表示状态 |
| `--grad` 变量 | 全局渐变 token | 已删除，避免以后又被复用 |

"卡片当容器"这条是 Impeccable 明确点名的懒惰做法：

> 同尺寸的「图标 + 标题 + 文字」卡片当成页面结构；卡片是懒惰的容器，嵌套卡片永远是错的。

服务器列表的信息密度本来就低，用卡片等于给每行加了一圈没有信息量的边框。改成行式列表后，
一屏能多看几台，扫读更快。

## 23 条逐项自查

分五组。结论只有两种：**合规**（代码里能对上）和 **已改**（这次动过手）。

|---|---|---|---|
| 1 | 一屏只服务一个主任务 | 登录页：一个输入框 + 一个按钮；列表页：只做"选服务器"；终端页：终端占满 | 合规 |

## 尺寸实测

同一套样式在三个真实视口跑过，截图见 `docs/`：

| 视口 | 页面 | 结果 |
|---|---|---|
| 390×780（手机，DPR 2） | 登录 / 列表 / 终端 / 状态 | 单列、留白均衡、终端可读 |
| 1024×768（平板） | 列表 | 已进入限宽，行宽不超过 760 |
| 1440×900（PC） | 登录 / 列表 / 终端 | 列表居中不拉伸；终端铺满，字号 16 |

终端在 1440 宽下如果沿用 14px，字符会细到看不清；16px 是这块屏幕上的上限——
再大，一行就装不下 `df -h` 那种 100+ 字符的输出。

## 已知取舍

- **星点在宽屏更稀**：1440 屏上只补了 11 颗，不追求"满天星"。再密就会干扰阅读，这是刻意的。
- **列表页留白很大**：只有两台服务器时，下半屏是空的。没有做"填充内容"的假区块，空着就是空着。
- **不用玻璃拟态做浮层**：状态面板是实色 + 边框 + 柔和阴影，因为毛玻璃在半透明背景下会糊掉一屏终端内容。
- **终端字号不做流体缩放**：`clamp()` 会让不同窗口宽度下的列数不可预测，SSH 终端需要确定的字符网格。
